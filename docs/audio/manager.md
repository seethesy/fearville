# Shared audio manager

`lib/audio/tracks.json` maps music contexts and effects to audio files. Art's tracks can replace these data values without playback-code changes. Use versioned filenames so browser caches refresh. Optional `rite.board`, `rite.grid`, `rite.lab` and `rite.ritual` entries override the shared `rite` fallback. Voting can fall back to day. Music is selected from the public phase/result and the viewer's own Rite pattern, with the same phase policy for Storyteller and players. No hidden roles/actions/messages are used.

The app-level provider owns one manager and binds trusted pointer/keyboard gestures, browser visibility and the existing FEAR-96 native lifecycle bridge. Music defaults to zero volume. No AudioContext, fetch or decode occurs until a user gesture; muted music never loads. Tracks loop and crossfade over 0.6 seconds. Volume/background changes apply to active voices; obsolete async loads are stopped before becoming audible. Audio fetch/decode failures stay silent and never block game controls. The decoded-buffer cache is bounded to eight files and browser HTTP caching is enabled.

The same manager handles the existing phase/error cues with independent SFX volume. Native cues retain the existing bridge delegation and silent-switch behavior; browsers use short original PCM cue files. The synthesized oscillator music bed is removed entirely. Reduced-motion settings affect visuals only. Background muting follows the existing setting; the OS may also suspend a WebView's audio context. Foregrounding attempts to resume a previously unlocked context, with another gesture available if the platform blocks it.

`public/audio/placeholder.wav` is silent on purpose. `phase.wav` and `error.wav` are original short descending tones. All three are generated by `node scripts/generate-audio-placeholders.mjs`; WAV metadata includes the GENERATED source notice. Regenerate rather than editing them. No third-party licenses or music credits are needed for these placeholders; actual music and credits belong to FEAR-167.

Known remaining scope: ordinary `AppLink` anchors load a new document, so they interrupt audio across hub → profile/rules routes. Within the same mounted document, unchanged tracks continue without restarting. FEAR-203 tracks a persistent owner or verified navigation repair. Do not claim uninterrupted full-document navigation is complete.

Testing: context/track selection, gesture gating, settings, crossfades, background behavior, obsolete-load races, native cue selection, silent failures and lazy decode caching are unit tested. In Test should include Safari/Chrome and Capacitor lifecycle, volume, mute and crossfade checks with an audible temporary track; the silent placeholder cannot demonstrate audible music transitions. No native builds or deployment were run.
